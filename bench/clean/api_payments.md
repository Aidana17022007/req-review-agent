# Чистое ТЗ (вымышленное): API оплаты коммунальных услуг для партнёрского приложения

> Вымышленный документ без внесённых дефектов — для замера ложных тревог агента. Не является документом организаторов.

## 1. Назначение и рамки

API позволяет партнёрскому приложению оплачивать коммунальные услуги со счёта клиента банка.
Вне рамок: регулярные автоплатежи, оплата штрафов, возврат платежей, данные платёжных карт (API списывает только со
счёта клиента, номера карт и CVV через API не передаются — требования PCI DSS к нему не применяются).

## 2. Термины

- **Партнёр** — компания с договором на использование API и выданным ключом клиента OAuth 2.0.
- **Поставщик** — организация из справочника «Поставщики» с кодом поставщика из 6 цифр.
- **Идентификатор запроса** — строка UUID версии 4, которую партнёр передаёт в заголовке Idempotency-Key.

## 3. Функциональные требования

| ID | Требование | Приоритет |
| :--- | :--- | :--- |
| AP-01 | Метод GET /v1/providers возвращает список поставщиков: код, название, тип услуги; список обновляется раз в сутки в 03:00 по времени Алматы. | Высокий |
| AP-02 | Метод GET /v1/bills?providerCode=…&account=… возвращает задолженность клиента у поставщика в тенге с точностью до 1 тиына. | Высокий |
| AP-03 | Метод POST /v1/payments создаёт платёж: providerCode (6 цифр), account (строка 1–20 символов), amount (целое число тиынов от 100 до 50 000 000). | Высокий |
| AP-04 | Повторный POST /v1/payments с тем же Idempotency-Key в течение 24 часов не создаёт второй платёж и возвращает результат первого. | Высокий |
| AP-05 | Платёж получает статус «accepted» сразу после списания и «completed» после подтверждения поставщиком; при отказе поставщика — «rejected», деньги возвращаются на счёт не позднее 1 часа. | Высокий |
| AP-06 | Метод GET /v1/payments/{id} возвращает статус платежа, сумму, время создания и время последнего изменения статуса. | Высокий |
| AP-07 | Комиссия банка за платёж — 0 тиынов. | Средний |

## 4. API: ответы

| Код | Когда | Тело ответа |
| :--- | :--- | :--- |
| 200 | Успешное чтение | данные ресурса |
| 201 | Платёж создан | {"id":"…","status":"accepted"} |
| 400 | Параметр отсутствует или неверного формата | {"code":"VALIDATION_ERROR","field":"amount","message":"…"} |
| 401 | Нет или истёк токен | {"code":"UNAUTHORIZED","message":"…"} |
| 402 | Недостаточно средств | {"code":"INSUFFICIENT_FUNDS","message":"…"} |
| 404 | Поставщик или платёж не найден | {"code":"NOT_FOUND","message":"…"} |
| 409 | Idempotency-Key уже использован с другими параметрами | {"code":"IDEMPOTENCY_CONFLICT","message":"…"} |
| 503 | Поставщик недоступен | {"code":"PROVIDER_UNAVAILABLE","message":"…","retryAfter":60} |

## 5. Нефункциональные требования

| ID | Требование | Приоритет |
| :--- | :--- | :--- |
| ANF-01 | POST /v1/payments отвечает не дольше 2 секунд для 95 % запросов при нагрузке до 200 запросов в секунду. | Высокий |
| ANF-02 | Доступность API — не менее 99,9 % в календарный месяц без учёта плановых работ, объявленных партнёрам за 72 часа. | Высокий |
| ANF-03 | API доступен только по TLS версии 1.2 и выше. | Высокий |
| ANF-04 | Журнал аудита записывает каждый запрос: партнёр, метод, Idempotency-Key, код ответа, время; журнал хранится 5 лет; токены в журнал не записываются. | Высокий |
| ANF-05 | Партнёру разрешено не более 100 запросов в секунду; при превышении — ответ 429 с заголовком Retry-After. | Средний |
| ANF-06 | При доле ответов 5xx выше 1 % за 5 минут мониторинг отправляет оповещение дежурной смене. | Средний |
| ANF-07 | Резервная копия платежей создаётся каждый час; RTO — 2 часа, RPO — 5 минут. | Средний |
| ANF-08 | Тексты сообщений об ошибках возвращаются на казахском или русском языке по заголовку Accept-Language. | Низкий |

## 6. Безопасность и соответствие

| ID | Требование | Приоритет |
| :--- | :--- | :--- |
| AS-01 | Доступ — по OAuth 2.0 (client credentials) и токену клиента, полученному после его входа в приложение банка; срок токена клиента — 15 минут. | Высокий |
| AS-02 | Каждый платёж проверяет антифрод-система банка; платёж с признаком мошенничества получает статус «rejected». | Высокий |
| AS-03 | Партнёр видит только платежи, созданные его ключом. | Высокий |
| AS-04 | Номер лицевого счёта клиента у поставщика в ответах API показывается полностью только партнёру, создавшему платёж. | Средний |
| AS-05 | Клиент даёт согласие на передачу данных партнёру при подключении партнёрского приложения в приложении банка. | Высокий |

## 7. Критерии приёмки

| Требование | Исходные условия | Действие | Ожидаемый результат |
| :--- | :--- | :--- | :--- |
| AP-01 | Справочник обновлён | GET /v1/providers | 200 и список с кодом, названием, типом услуги |
| AP-02 | Задолженность 12 345,67 ₸ | GET /v1/bills | 200 и сумма 1234567 тиынов |
| AP-03 | amount = 99 | POST /v1/payments | 400, code VALIDATION_ERROR, field amount |
| AP-04 | Платёж с ключом K создан | Повторить POST с ключом K и теми же параметрами | Второй платёж не создан, возвращён результат первого |
| AP-04 | Платёж с ключом K создан | POST с ключом K и другой суммой | 409 IDEMPOTENCY_CONFLICT |
| AP-05 | Поставщик отклонил платёж | GET /v1/payments/{id} | Статус «rejected», деньги вернулись не позднее 1 часа |
| AP-06 | Платёж выполнен | GET /v1/payments/{id} | Статус «completed», сумма, время создания и изменения |
| AP-07 | Платёж 10 000 ₸ | Создать платёж | Списано 10 000 ₸ |
