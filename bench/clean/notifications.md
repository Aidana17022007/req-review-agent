# Чистое ТЗ (вымышленное): Уведомление о достижении месячного порога расходов

> Вымышленный документ без внесённых дефектов — для замера ложных тревог агента. Написан командой ReqLens на свою тему, не копия документа организаторов.

## 1. Назначение и рамки

Функция сообщает держателю, что его расходы по карте за календарный месяц достигли заданного порога.
Вне рамок: пороги по кредитным картам, уведомления по SMS, пороги в иностранной валюте.

## 2. Термины

- **Держатель** — клиент банка с активной дебетовой картой в тенге, вошедший в мобильное приложение.
- **Расходы месяца** — сумма проведённых покупок по карте за календарный месяц по дате совершения покупки по времени Алматы; переводы и снятие наличных не входят.
- **Порог** — целое число тенге от 1 000 до 1 000 000 включительно, заданное держателем; до первого сохранения порог не задан и уведомление выключено.
- **Действующая сессия** — сессия держателя после входа в приложение по ПИН-коду или биометрии, с Bearer-токеном, выданным не более 10 минут назад после последнего действия.

## 3. Функциональные требования

| ID | Требование | Приоритет |
| :--- | :--- | :--- |
| NT-01 | Держатель включает уведомление переключателем и задаёт порог на экране «Карты → Расходы → Уведомления»; по умолчанию уведомление выключено. | Высокий |
| NT-02 | Когда расходы месяца впервые в этом месяце становятся равны порогу или больше, держатель получает одно push-уведомление. | Высокий |
| NT-03 | В текущем месяце после отправки уведомления повторные уведомления не отправляются, даже если порог изменён. | Высокий |
| NT-04 | При изменении порога расходы месяца не сбрасываются; уведомление по новому порогу отправляется по правилу NT-02, если в этом месяце оно ещё не отправлялось. | Высокий |
| NT-05 | Возврат покупки, в том числе частичный возврат, уменьшает расходы месяца исходной покупки на сумму возврата; уже отправленное уведомление не отзывается, и повторно в этом месяце уведомление не отправляется, даже если расходы снова достигли порога. | Средний |
| NT-06 | Push-уведомление содержит порог, расходы месяца и последние 4 цифры карты. | Средний |
| NT-07 | Метод чтения настроек: GET /alerts/limit?cardId=… возвращает порог и признак включения. | Высокий |
| NT-08 | Метод сохранения настроек: PUT /alerts/limit с телом {"cardId","amount","enabled"}; повторное сохранение тех же значений не меняет признак отправки в месяце. | Высокий |

## 4. API: ответы

| Код | Когда | Тело ответа |
| :--- | :--- | :--- |
| 200 | Настройки прочитаны или сохранены | {"amount":50000,"enabled":true} |
| 400 | Порог вне диапазона или не целое число | {"code":"LIMIT_OUT_OF_RANGE","message":"Порог от 1 000 до 1 000 000 ₸"} |
| 401 | Нет действующей сессии | {"code":"UNAUTHORIZED","message":"Требуется вход"} |
| 403 | Карта принадлежит другому клиенту | {"code":"FORBIDDEN","message":"Нет доступа к карте"} |
| 404 | Карта не найдена | {"code":"CARD_NOT_FOUND","message":"Карта не найдена"} |

## 5. Событие процессинга о покупке

Процессинг передаёт сервису расходов событие о каждой проведённой операции по карте в формате JSON; доставка не реже одного раза (at-least-once), повтор опознаётся по идентификатору операции.

| Поле | Тип | Описание |
| :--- | :--- | :--- |
| operationId | string | уникальный идентификатор операции |
| cardId | string | идентификатор карты |
| type | string | PURCHASE, REFUND, TRANSFER или CASH |
| amount | integer | сумма в тиынах |
| originalOperationId | string | для REFUND — идентификатор исходной покупки |
| performedAt | string | дата и время совершения по ISO 8601 с часовым поясом |

## 6. Нефункциональные требования

| ID | Требование | Приоритет |
| :--- | :--- | :--- |
| NNF-01 | Push передаётся сервису отправки не позднее 60 секунд после получения события о покупке для 99 % событий при нагрузке до 300 событий в секунду. | Высокий |
| NNF-02 | Доступность сервиса настроек — не менее 99,9 % в календарный месяц без учёта плановых работ, объявленных за 48 часов. | Высокий |
| NNF-03 | Обмен с приложением и процессингом идёт только по TLS версии 1.2 и выше. | Высокий |
| NNF-04 | Журнал аудита записывает каждое изменение настроек и каждую отправку уведомления: держатель, карта (последние 4 цифры), значение, время; журнал хранится 3 года. | Высокий |
| NNF-05 | Событие о покупке с уже обработанным идентификатором операции не учитывается повторно. | Высокий |
| NNF-06 | При задержке событий процессинга дольше 5 минут мониторинг отправляет оповещение дежурной смене. | Средний |
| NNF-07 | Резервная копия настроек создаётся каждые 24 часа; RTO — 4 часа, RPO — 15 минут. | Низкий |
| NNF-08 | Экран настроек доступен на казахском и русском языках и соответствует WCAG 2.1 уровня AA. | Средний |

## 7. Безопасность и соответствие

| ID | Требование | Приоритет |
| :--- | :--- | :--- |
| NS-01 | Методы доступны только с действующей сессией держателя (Bearer-токен); сессия завершается после 10 минут бездействия. | Высокий |
| NS-02 | Держатель читает и меняет настройки только своих карт; чужая карта — ответ 403. | Высокий |
| NS-03 | Номер карты в уведомлениях и журналах показывается маскированным: только последние 4 цифры; токены сессии в журналы не записываются. | Высокий |

## 8. Критерии приёмки

| Требование | Исходные условия | Действие | Ожидаемый результат |
| :--- | :--- | :--- | :--- |
| NT-01 | Новый держатель | Открыть экран уведомлений | Переключатель выключен |
| NT-02, NT-06 | Включено, порог 50 000 ₸, расходы 48 500 ₸ | Покупка 1 500 ₸ | Одно push с порогом 50 000 ₸, расходами 50 000 ₸ и последними 4 цифрами карты |
| NT-03 | Уведомление в этом месяце отправлено | Покупка 10 000 ₸ | Повторного push нет |
| NT-04 | Уведомление не отправлялось, расходы 30 000 ₸ | Изменить порог на 25 000 ₸ | Расходы 30 000 ₸ сохранены; push отправлен при следующей покупке |
| NT-05 | Расходы 52 000 ₸, push отправлен | Возврат 5 000 ₸ | Расходы 47 000 ₸, повторного push нет |
| NT-07 | Порог 50 000 ₸ сохранён | GET /alerts/limit | 200 и {"amount":50000,"enabled":true} |
| NT-08 | Порог 50 000 ₸ сохранён | PUT /alerts/limit с amount 999 | 400 и код LIMIT_OUT_OF_RANGE |
| NS-02 | Чужая карта | GET /alerts/limit | 403 и код FORBIDDEN |
