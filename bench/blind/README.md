# Слепая оценка ReqLens

Бенчмарк `bench/run.py` и разметка документа организаторов (`bench/real/`) составлены командой — это оценка «изнутри».
Слепая оценка проверяет агента на документах, которые команда **не писала и не видела** до прогона.

## Правила

1. **Документы пишет не команда.** Короткое финтех-ТЗ (MD / DOCX / PDF) с намеренно внесёнными дефектами готовит автор,
   не видевший код агента. v14: первый набор (`ai_*`) написал и разметил **отдельный ИИ-агент**, которому не показывали
   код, промпты, словари, правила, `bench/` и отчёты ReqLens — только определение дефекта по ТЗ хакатона (ISO/IEC/IEEE
   29148 §5.2.5–5.2.6, IEEE 830 §4.3). Это не человек: набор человека вне команды — `KIT_outside_reviewer.md` (задача F),
   его файлы — без префикса `ai_`, вердикты в них вписывают только люди.
2. **Эталон закоммичен до прогона.** Документы и ключи кладутся в репозиторий **до** прогона агента отдельным коммитом;
   основной агент ключи не открывает — их читает только скрипт оценки. Коммит ключей печатается в результате.
3. **Агент на них не настраивается.** После получения документов в правила, промпты и словари агента ничего не меняется
   до публикации результата. Прогон — один, профилем `deep`, с чистого коммита (паспорт отчёта это показывает).
4. **Результат публикуется как есть** — раздел «Слепые документы» в `bench/RESULTS.md` (модель, версия агента, дата,
   коммит ключей) и подробности по документам в `bench/blind/RESULTS.md`, даже если он хуже ожиданий.

## Формат (v14)

- Документ: `bench/blind/docs/<имя>.md` (или `.docx`, `.pdf`).
- Текстовый слой для DOCX / PDF: `bench/blind/text/<имя>.txt` — тот же текст в порядке чтения, абзац = строка, строка
  таблицы — ячейки через ` | `. Номера строк ключа считаются по нему (для `.md` — по самому документу).
- Ключ: `bench/blind/keys/<имя>.json` — формат внешней разметки `bench/external/annotations.template.json`
  (строки, класс, серьёзность, заметка) плюс заведомо чистые требования:

```json
{"document": "bench/blind/docs/ai_loans.docx", "source": "bench/blind/text/ai_loans.txt", "title": "…",
 "format": "docx", "language": "kk", "annotator": "кто размечал", "date": "2026-11-27",
 "defects": [{"lines": [12, 30], "class": "contradiction", "severity": "critical", "note": "своими словами"}],
 "clean": [{"lines": [18], "note": "почему требование чистое"}]}
```

Оценка — `bench/external/score.py`: дефект найден, если цитата замечания агента лежит в отмеченных строках (±1) и
критерий замечания совместим с классом (таблица классов — `bench/external/PROTOCOL.md`). Формулировки не сравниваются.
Замечание в строках чистого требования, не совпавшее ни с одним дефектом, — ложное. Точность считается двумя способами:
по размеченным (совпавшие / (совпавшие + ложные к чистым)) и строгая (всё, чего нет в ключе, — ложное). 95 % интервалы —
перцентильный бутстреп, 1000 повторов, seed 13.

Прежний формат ключа (v9, регулярные выражения по тексту замечания, как `bench/real/notifications.json`) по-прежнему
понимается `bench/blind_eval.py` — формат определяется по полям дефектов.

## Запуск

```bash
python bench/blind_eval.py --env .env                   # ReqLens, профиль deep → bench/blind/reports/agent/
python bench/blind_eval.py --env .env --mode baseline   # «голая» модель, 1 запрос на документ → reports/baseline/
python bench/blind_eval.py --mode rules                 # только правила, без модели → reports/rules/
python bench/blind_eval.py --compare --results          # оценка всех режимов без прогона → bench/RESULTS.md
```

`--reports DIR` — оценить уже готовые отчёты `DIR/<имя>.json` без нового прогона (квота не тратится); `--docs`,
`--keys` — свои папки.
