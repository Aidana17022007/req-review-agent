# БЕНЧМАРК (вымышленный документ): Требования к перевыпуску банковской карты

> Вымышленный документ для измерения точности агента. Не является документом организаторов. Исходник в Markdown:
> генератор `bench/inject.py` собирает из него DOCX, где требования лежат в таблицах Word.

## 1. Термины

| Термин | Определение |
| :--- | :--- |
| Держатель | Физическое лицо, на имя которого выпущена карта банка. |
| Перевыпуск | Выпуск новой карты взамен действующей с сохранением счёта. |
| Заказ | Заявка держателя на перевыпуск карты в мобильном приложении. |

## 2. Функциональные требования

| ID | Требование | Приоритет |
| :--- | :--- | :--- |
| CRD-01 | Система должна отображать держателю список его карт с указанием последних четырёх цифр номера и срока действия. | Высокий |
| CRD-02 | Система должна позволять заказать перевыпуск карты не ранее чем за 60 дней до окончания срока её действия. | Высокий |
| CRD-03 | Система должна списывать комиссию 0 тенге за плановый перевыпуск карты по окончании срока действия. | Средний |
| CRD-04 | Система должна запрашивать подтверждение заказа одноразовым кодом из SMS, действующим 120 секунд. | Высокий |
| CRD-05 | Система должна блокировать подтверждение заказа на 30 минут после 3 неверных вводов кода подряд. | Высокий |
| CRD-06 | Система должна блокировать старую карту не позднее 5 минут после активации новой карты. | Высокий |
| CRD-07 | Система должна хранить историю заказов на перевыпуск в течение 5 лет. | Низкий |
| CRD-08 | Система должна позволять выбрать способ получения карты: в отделении или курьером. | Средний |
| CRD-09 | Система должна отправлять держателю push-уведомление о готовности карты в течение 60 секунд после смены статуса заказа. | Средний |
| CRD-10 | Система должна присваивать заказу один из статусов: «Создан», «Изготавливается», «Готова к выдаче», «Выдана», «Отменён». | Высокий |
| CRD-11 | Система должна позволять отменить заказ до смены его статуса на «Изготавливается». | Средний |
| CRD-12 | Система должна показывать держателю причину отказа в перевыпуске из справочника кодов отказа. | Средний |
| CRD-13 | Система должна позволять держателю указать адрес доставки длиной до 200 символов. | Низкий |
| CRD-14 | Система должна сохранять номер счёта карты при перевыпуске. | Высокий |

## 3. Нефункциональные требования

| ID | Требование | Приоритет |
| :--- | :--- | :--- |
| KNF-01 | Время ответа на запрос списка карт не должно превышать 2 секунд для 95 % запросов при нагрузке до 200 запросов в секунду. | Высокий |
| KNF-02 | Доступность сервиса перевыпуска должна составлять не менее 99,9 % в календарный месяц без учёта плановых работ. | Высокий |
| KNF-03 | Данные заказов должны храниться в зашифрованном виде алгоритмом AES-256. | Высокий |
| KNF-04 | Система должна записывать в журнал аудита каждый заказ на перевыпуск с указанием идентификатора держателя, времени и результата. | Средний |
| KNF-05 | Резервная копия базы заказов должна создаваться каждые 24 часа и храниться 30 дней. | Средний |
| KNF-06 | Интерфейс сервиса должен быть доступен на казахском и русском языках. | Низкий |
