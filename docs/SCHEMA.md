# Формат report.json (контракт backend ↔ UI)

Версия схемы: **2.5**. Правило: изменения только добавляющие — поля 2.0 не переименовываются и не удаляются.

## Что добавлено в 2.5 · v12 (исправленное ТЗ после ответов)

Только при `--answers`; версия схемы не меняется (поля только добавлены в объект `answers`).

| Поле | Тип | Смысл |
|---|---|---|
| `answers.revised.changed[]` | объект | `{"rid","doc_id","before","after","fixes","qids","quotes","source"}` — требование, изменённое ответом: `before` — дословно из документа, `after` — новая формулировка со значениями из ответа, `fixes` — закрытые замечания (`R-xxx.N`, `S-xx`), `qids` — вопросы, `quotes` — дословные цитаты ответов, `source` — `"ответ"` |
| `answers.revised.added[]` | объект | `{"id","text","from","fixes","quote"}` — новое требование (`NEW-01` …) по пропуску набора, закрытому ответом `from` (Q-xx) |
| `answers.revised.acceptance[]` | объект | `{"rid","gherkin","source"}` — критерий приёмки Дано / Когда / Тогда к изменённому (`R-xxx`) или новому (`NEW-xx`) требованию; есть только при прогоне с моделью |
| `answers.revised.open[]` | объект | `{"qid","rid","type","placeholder","quote","text"}` — что осталось уточнить: `type` — `evasive`, `contradictory` или `без ответа` (критичный вопрос без ответа); `placeholder` — «[уточнить: Q-xx …]»; `text` — текст требования с плейсхолдером |
| `answers.revised.suggestions[]` | объект | `{"rid","doc_id","before","after","source":"предложение агента"}` — правки, которые агент предлагает сам, без ответа аналитика |
| `answers.summary` | объект | `{"blockers_total","blockers_closed","open_before","open_after","closed_blockers"}`: критичных до ответов / закрыто ответами; открытых замечаний до / после; `closed_blockers[]` — `{"id","qid","quote","severity","criterion","problem"}` |

**Проверка «Стало».** Формулировку пишет модель (задача `revise`); каждое число в `after` и `gherkin` должно быть в
исходном требовании или в цитате ответа (идентификаторы R-/Q-/S- не считаются), иначе формулировка отклоняется и
остаётся шаблон «исходный текст + решение из ответа». Без модели — только шаблон, критериев приёмки нет.

**Варианты ответа.** В `<имя>_answers_template.md` у вопросов с повесткой решений (`decisions`) или противоречием с
двумя значениями — блок «*Варианты (можно ответить буквой):*» и строки «- а) …», «- б) …», «- в) свой ответ». Ответ
«б» или «б, но …» разбирается в текст варианта (+ уточнение) и считается конкретным (в `answers.items[].note` — «выбран вариант б)»).

Артефакты: `<имя>_revised.md` (и `<имя>_revised.pdf` в профиле deep) — разделы «Изменённые требования» (Было → Стало,
«Устраняет: … · по ответу Q-xx: «цитата»»), «Новые требования», «Новые критерии приёмки», «Осталось уточнить»,
«Предложения агента». В `<имя>.md` перед разделом 1 — блок «Кратко: что изменилось после ответов аналитика».

## Что добавлено в 2.5 (v10: чек-лист банка)

`bank_rules` — есть только при прогоне с `--rules ФАЙЛ` (или `REQLENS_RULES`); без флага поля нет.

| Поле | Тип | Смысл |
|---|---|---|
| `name`, `file`, `disclaimer` | строка | название набора, имя файла правил, оговорка из файла |
| `total`, `enabled`, `disabled` | число | правил всего / включено / выключено (`enabled: false` с причиной) |
| `fired`, `passed`, `not_applicable` | число | правил сработало / выполнено / не применимо (нет подходящих требований) |
| `findings` | число | замечаний, добавленных правилами |
| `rules[]` | объект | `id`, `title`, `severity`, `criterion`, `criterion_name`, `scope` (`requirement` \| `document`), `reference`, `applicable`, `hits`, `status` (`fired` \| `passed` \| `not_applicable` \| `disabled`), `where` (R-xxx), `reason` (для выключенных) |

Замечания правил лежат в обычных местах: `requirements[].findings[]` (scope `requirement`) и `set_findings[]` с
`kind: "bank_rule"` (scope `document`). Их `source` — «правило банка: <id>». Если замечание совпало с уже найденным
(тот же критерий и цитата), к его `source` добавляется « + правило банка: <id>». Цитаты дословные (`verify.quote_in`).

`passport.time_estimate` (v10, есть в каждом прогоне) — **оценка**, не замер: `doc_lines` (непустые строки документа),
`lines_per_hour` (норма из `REVIEW_LINES_PER_HOUR`, по умолчанию 40), `norm_source`, `manual_hours` = doc_lines ÷
lines_per_hour (1 знак), `agent_minutes` (фактическая длительность прогона агента), `estimate: true`.

## Что добавлено в 2.4 (v9: ответы аналитика, решения, журнал)

Пример со всеми полями — `tests/fixtures/report_v9.json` (mock-прогон; по нему можно делать интерфейс, не дожидаясь
движка). Новые поля появляются только с флагами (`--answers`) или там, где есть что показать; без них прогон как раньше.

**Идентификаторы.** Замечание к требованию — `R-xxx.N` (N — номер замечания у этого требования, с 1, как `fid` в
HTML-отчёте), замечание к набору — `S-xx`, вопрос — `Q-xx`, решение — `D-xx`. В прогоне с ответами `closes` и `source_ids`
ссылаются на номера **исходного** прогона (до ответов): закрытые замечания уходят в `rejected[]` с `closed_by`, остальные
перенумеровываются, новое замечание «ответ противоречив» добавляется в конец `set_findings`.

| Поле | Где | Описание |
|---|---|---|
| `questions[].qid` | вопрос | `Q-01`, `Q-02`, … в порядке списка; тот же ID — заголовок `### Q-01` в шаблоне ответов |
| `questions[].closes` | вопрос | ID замечаний, которые закроет конкретный ответ: `["R-002.1"]` / `["S-03"]` |
| `questions[].refs` | вопрос | для вопроса к набору — затронутые требования `["R-013","R-014"]`: по ним ответ находит вопрос в новом прогоне (номера `S-xx` могут меняться) |
| `passport.answers` | паспорт | только при `--answers`: `{"file","items","closed"}` |
| `answers` | корень | только при `--answers`: `{"source","items","before","after"}` (ниже); без ответов — поля нет |
| `answers.source` | ответы | имя файла ответов (`answers.md`), без пути |
| `answers.items[]` | ответы | `{"qid","question","answer","type","closes","quote","note"}` — по одному на каждый вопрос, на который дан ответ |
| `answers.items[].type` | ответ | `concrete` — дал значение / решение → замечания из `closes` закрыты; `evasive` — уклончиво («уточним позже») → остаются открытыми с пометкой; `contradictory` — противоречит документу или другому ответу → остаются + новое замечание набора |
| `answers.items[].closes` | ответ | ID замечаний, закрытых этим ответом; у `evasive` и `contradictory` — `[]` |
| `answers.items[].quote` | ответ | дословный фрагмент ответа, на котором основан вывод (подстрока `answer`); без цитаты ничего не закрывается |
| `answers.items[].note` | ответ | что сделано: «R-002.1 закрыто: порог 2 с для 95 % запросов», «остаётся открытым: срок не назван» |
| `answers.before`, `answers.after` | ответы | `{"critical","major","readiness","verdict":{"development","testing"}}` — до и после учёта ответов |
| `rejected[].closed_by` | отклонённое | `Q-xx` — замечание закрыто ответом; `reason` = «закрыто ответом Q-xx» |
| `set_findings[].source` | замечание набора | новое значение `ответ Q-xx` — замечание «ответ противоречив» (цитата ответа в `values[]`, `rid` = `Q-xx`) |
| `decisions[]` | корень | повестка для владельца продукта, 0–8 пунктов: `{"id","title","where","impact","options","source_ids","wording"}` |
| `decisions[].where[]` | решение | `{"rid","doc_id","line"}` — где расходится документ (строка исходного файла) |
| `decisions[].impact` | решение | что меняется для клиента / разработки, одно предложение |
| `decisions[].options[]` | решение | 2–3 варианта решения, строки |
| `decisions[].source_ids` | решение | ID замечаний, из которых собран пункт |
| `decisions[].wording` | решение | `код` — формулировка из замечаний; `модель` — модель перефразировала на бизнес-язык |
| `passport.log` | паспорт | имя журнала прогона `<имя>.log` рядом с отчётом |
| `passport.cascade` | паспорт | только при `--cascade`: `{"fast","strong","strong_reqs","checked_reqs","calls":{"fast":N,"strong":M}}` — `fast`/`strong` — подписи моделей; сколько требований из проверенных ушло на сильную модель и обращения каждой |

Артефакты 2.4 (рядом с `<имя>.md`): `<имя>_answers_template.md` — все вопросы с заголовками `### Q-xx`, ссылками на
замечания и пустым местом для ответа; `<имя>_decisions.md` — повестка решений; `<имя>.log` — этапы, длительности,
модель, обращения / кэш / повторы, переключения моделей, отброшенные цитаты (без ключей и без текста документа).

## Уверенность 0–1

| Источник | Значение |
|---|---|
| тест-проба (тест составить невозможно, цитата подтверждена) | 0.95 |
| числовое противоречие, найденное правилом (и подтверждённое моделью) | 0.90 (0.95) |
| подтверждено критиком и двумя источниками (модель + правило) | 0.90 |
| подтверждено критиком | 0.75 |
| только правило / доменный чек-лист | 0.60 |
| только модель, без критика | 0.55 |
