# Питч ReqLens — сценарий на 3 минуты

Слайды: `docs/slides.html` (стрелки ← → для навигации, `P` — печать в PDF). Сгенерировать заново: `python -m req_review.ui.styleguide`.

## 0:00–0:25 · Проблема
- Дефект в требованиях, найденный после релиза, стоит на порядки дороже, чем найденный на ревью (ориентир из литературы — до ~100×).
- Ревью требований делают вручную, долго и по-разному. Слова «быстро», «удобно», «и т. д.» доходят до разработки и тестирования.

## 0:25–1:45 · Живое демо (главное)
Подготовка: `python -m req_review.web` (ReqLens Studio) и прогон того же документа заранее — кэш ответов модели делает повтор мгновенным.
0. **Живой прогон**: перетащите файл в Studio — таймлайн шагов и таблица требований заполняются вживую (GIF: `docs/assets/live-run.gif`).
1. **Hero**: индикатор «Готовность к разработке NN%», вердикт крупно — «Начинать разработку нельзя / можно условно / можно».
2. Вкладка **«Документ»**: дефекты подчёркнуты прямо в тексте, как в Grammarly. Нажмите `J` — переход к следующему дефекту,
   справа панель: критерий, пункт ISO 29148, проблема, как исправить, готовая формулировка → «Скопировать».
3. Вкладка **«Тесты»**: «к этому требованию тест написать невозможно — вот фрагмент, который мешает». Это не мнение модели, а проверка.
4. Вкладка **«Граф»** (3D): красное ребро — противоречие; клик по узлу — цепочка конфликта (кнопка «2D» — запасной вид).
5. Вкладка **«Исправления»**: diff «было → стало», «Скачать исправленный документ», вопросы аналитику (экспорт в .md).
6. **AI-ассистент** в Studio: «Почему R-006 критичное?» — ответ со ссылками, клик открывает требование в отчёте.
7. **«До / После»**: «Проверить исправленный агентом» — балл и готовность растут на глазах. ← кульминация.

## 1:45–2:20 · Почему этому можно доверять
- Каждое замечание — с дословной цитатой; цитату проверяет код, выдуманное отбрасывается (видно в приложении отчёта).
- Критик-агент перепроверяет замечания и ставит уверенность.
- Бенчмарк на документе с заранее известными дефектами: число дефектов, recall и precision называем ТОЛЬКО
  из `bench/RESULTS.md` после прогона на модели (с указанием модели и даты). Цифры mock-прогона не озвучиваем.
- Все баллы считает код по формулам из приложения «Методика оценки».

## 2:20–2:45 · Для банка
- Финтех-чек-лист полноты: 2FA, лимиты, идемпотентность, AML, персональные данные (Закон РК), SLA, RTO/RPO.
- `--profile offline`: локальная модель через Ollama — документ не покидает контур банка.
- Excel-трассировка и CSV для Jira — результат сразу уходит в работу команды.

## 2:45–3:00 · Что дальше
- Подключение к Confluence/Jira, ревью при каждом изменении требований в PR (`examples/requirements-review.yml`).
- Новые домены чек-листов (страхование, госуслуги) — одним YAML-файлом.
