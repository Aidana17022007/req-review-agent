Проблема
~100×

Ориентир из литературы: дефект требований, найденный в эксплуатации, обходится на порядки дороже, чем найденный на ревью. «Быстро», «удобно», «и т. д.» доходят до кода — и до инцидентов. Ручное ревью — долго, субъективно и без трассировки.

Доверие

Почему нам можно верить

1 · Аудит цитат

Каждое замечание — с дословной цитатой и номером строки. Код сверяет каждую цитату с документом; выдуманная — замечание отбрасывается. Итог аудита — первая строка отчёта.

«Цитат в замечаниях — N, подтверждено в документе — N, отброшено как выдуманные — M. Учтено строк документа: X из X.»
2 · Основание в норме

RAG находит пункт стандарта, закон РК или шаблон и прикладывает фрагмент базы знаний с источником — «по памяти» модель не цитирует.

ISO/IEC/IEEE 29148 · п. 5.2.5 d) Complete — пересказ своими словами; законы РК — со ссылкой на adilet.zan.kz
3 · Бенчмарк: найдено 67 из 67 внедрённых дефектов

Модель: gemini / gemini-3.5-flash-lite. Колонка «с RAG» — после прогона bench/run.py с базой знаний.

Только измеренные цифры: bench/RESULTS.md, модель и дата прогона указаны в файле. Баллы считает код по формулам из «Методики оценки».

Устойчивость

Работает, даже когда модель недоступна

Без модели

Квота закончилась или нет сети — LLM_PROVIDER=rules: детерминированные правила находят размытые формулировки, плейсхолдеры, числовые конфликты, ошибки API, отсутствие метода чтения и контракта событий. В паспорте это честно указано.

Незнакомый документ

В бенчмарке есть документ с формулировками дефектов, которых агент не видел при разработке, — проверка, что правила общие, а не подогнаны под один текст.

Исправил → проверил заново

--fix-loop: агент переписывает формулировки, проверяет исправленный документ и показывает «До / После» — балл, готовность, критичные и что осталось решить аналитику.

Повторить прогон может любой: Actions → Generate report со своим ключом — отчёт в md, html, json и pdf.
