# Демо ReqLens на защите — сценарий на 3 минуты

## Подготовка (до выхода на сцену)

1. **Финальный отчёт** по документу организаторов (уже лежит в репозитории: `reports/requirements-report.md`,
   `.html`, `.pdf`, `.json`). Повторить прогон:
   ```bash
   python review.py docs/requirements.md reports/requirements-report.md --profile deep
   ```
2. **«До / После»** — агент исправляет формулировки и проверяет исправленный документ заново:
   ```bash
   python review.py docs/requirements.md reports/demo/report.md --fix-loop
   ```
   Итог — `reports/demo/report_before_after.md` (балл, готовность, критичные до и после, что осталось аналитику).
3. **Studio в режиме «Демо»** — сеть и квота модели на сцене не нужны:
   ```bash
   python -m req_review.web --demo reports/requirements-report.json
   ```
   Откроется `http://localhost:8000`, на стартовом экране — кнопка **«Демо»**. Загрузка своего файла запускает
   настоящую проверку (нужен ключ).

> Страховка: нет интернета или кончилась квота — режим «Демо» проигрывает сохранённый реальный прогон без модели;
> для нового файла — `LLM_PROVIDER=rules` (только детерминированные правила, в паспорте так и написано).

## Сценарий

| Время | Что показываем | Что говорим |
|---|---|---|
| 0:00–0:20 | Стартовый экран Studio → кнопка **«Демо»** (или перетащить файл) | «Агент читает ТЗ банка и проверяет каждое требование и набор целиком по ISO/IEC/IEEE 29148 и IEEE 830.» |
| 0:20–0:45 | **Живой прогон**: таймлайн шагов, требования появляются в таблице пакетами | «Модель предлагает — код проверяет: каждая цитата сверяется с документом.» |
| 0:45–1:10 | Отчёт → **«Итог за 30 секунд»** и полоса доверия: «Аудит цитат N из N», «Учтено строк X из X» | «Вердикт для разработки и тестирования, что исправить первым — с примером формулировки. Выдуманных цитат 0.» |
| 1:10–1:35 | **«Документ»**: подчёркивания по тяжести, клик — карточка с критерием, основанием в норме и правкой | «Как проверка орфографии, только для требований: GET для сохранения, ERROR в ответе 200, нет метода чтения.» |
| 1:35–1:55 | **Матрица «требование × критерий»** и **покрытие приёмкой** | «Видно, какие правила вообще не покрыты примерами приёмки — тестировщик не сможет их принять.» |
| 1:55–2:20 | **«До / После»** (`--fix-loop`) | «После правок агента: балл N → M, критичных K → L; остальное требует решения аналитика — данных в документе нет.» |
| 2:20–2:40 | Слайд **«Почему нам можно верить»**: бенчмарк (recall/precision, модель и дата из `bench/RESULTS.md`) | «Мы измеряем точность на документах с известными дефектами, включая незнакомый агенту.» |
| 2:40–3:00 | **Actions → Generate report** (или AI-ассистент с источниками) | «Любой из жюри повторит прогон своим ключом в один клик — отчёт в md, html, pdf.» |

## Если что-то пошло не так

| Ситуация | Что делать |
|---|---|
| Нет интернета / лимит API | Кнопка «Демо» — прогон проигрывается из записи; для нового файла — `LLM_PROVIDER=rules` |
| Не открывается 3D | Кнопка «2D» в разделе «Граф» (включается сама, если нет WebGL) |
| Вопрос не по шаблону | Ассистент отвечает по `report.json` с источниками; при лимите API — ответ из источников без модели |
| Нужен отчёт на бумаге | `reports/requirements-report.pdf` или `Ctrl+P` в HTML-отчёте |
| Жюри говорит по-казахски | Пункт меню «Қазақша» — интерфейс на казахском (содержание отчёта — на русском по ТЗ) |
