# Пример: ответы аналитика → перепроверка

`organizers_answers.md` — 10 вымышленных ответов аналитика на вопросы отчёта ReqLens по документу организаторов
(`bench/real/notifications.md`): 6 конкретных, 2 уклончивых, 2 противоречивых. Ответы составлены командой своими
словами, чтобы показать, как агент учитывает каждый тип.

```bash
python review.py bench/real/notifications.md reports/answers/report.md --profile deep --answers examples/answers/organizers_answers.md
```

Ответы сопоставляются с вопросами нового прогона по служебной метке `<!-- reqlens: … -->`: для требования — ID и
критерий, для замечания к набору — критерий и затронутые требования (номера `S-xx` от прогона к прогону могут
меняться). Итог — раздел «Ответы аналитика» в «6. Итог», поле `answers` в `report.json`, исправленный документ с
формулировками из конкретных ответов.

## Тип ответа → ожидаемое → сделано верно

Колонка «Правила» — классификация правилами агента на вопросах отчёта для сдачи (v9.0.0, коммит b76ae21; без модели):
совпала во всех 10 случаях. Колонка «Прогон с моделью» — по факту прогона с `--answers` (профиль fast, gemini-3.5-flash-lite, 27.11.2026): 6 из 6 сопоставленных определены верно; 4 вопроса этот прогон не задал. Номера Q-xx — по
этому отчёту; в другом прогоне номера меняются, ответы находят свои вопросы по служебной метке.

| Вопрос | О чём | Ответ | Тип | Ожидаемое | Правила | Прогон с моделью |
|---|---|---|---|---|---|---|
| Q-01 | GET для сохранения (R-013, R-014) | PUT /alerts/limit, параметры в теле | конкретный | противоречие закрыто | ✅ | ✅ конкретный |
| Q-02 | 200 с ERROR и 400 (R-039) | ошибка суммы — только 400 | конкретный | противоречие закрыто | ✅ | ✅ конкретный |
| Q-06 | значение для Prod (R-017) | адрес Prod назван | конкретный | пропуск закрыт | ✅ | ✅ конкретный |
| Q-42 | стык месяцев (R-011) | месяц — по дате совершения покупки | конкретный | пропуск закрыт | ✅ | вопроса нет в прогоне |
| Q-51 | исходные условия примера (R-011) | переключатель, счётчик 0 ₸, покупка 4 000 ₸ | конкретный | пропуск закрыт | ✅ | вопроса нет в прогоне |
| Q-52 | перцентиль срока push (R-006) | 60 с для 99 % событий | конкретный | замечание закрыто | ✅ | вопроса нет в прогоне |
| Q-04 | контракт события (R-006, R-008) | «согласуем позже» | уклончивый | остаётся открытым, с пометкой | ✅ | вопроса нет в прогоне |
| Q-28 | токен и сессия (R-015) | «пока не решено» | уклончивый | остаётся открытым, с пометкой | ✅ | ✅ уклончивый |
| Q-07 | Ф-2 и пример (R-003, R-011) | 5 000 ₸ к февралю (в документе 4 000) | противоречивый | остаётся + замечание «ответ противоречив» | ✅ | ✅ противоречивый |
| Q-24 | 403 или 404 (R-043) | для чужой карты и 403, и 404 | противоречивый | остаётся + замечание «ответ противоречив» | ✅ | ✅ противоречивый |

Противоречие правила видят двумя способами. Первый — по числам: значение той же единицы, которого нет в документе
(Q-07). Второй — без чисел: одному и тому же случаю ответ назначает два разных HTTP-кода или метода из спорных
вариантов вопроса (Q-24). Разные случаи («403 — чужая карта, 404 — карта не найдена») противоречием не считаются.

Ничего не закрывается без дословной цитаты ответа: цитата хранится в `answers.items[].quote` и проверяется кодом как
подстрока ответа.

## Исправленная редакция ТЗ (v12)

С `--answers` агент дополнительно пишет `report_revised.md` (в профиле deep — и PDF): «Было → Стало» со значениями
из конкретных ответов, «Устраняет: S-xx · по ответу Q-xx» с дословной цитатой, новые требования `NEW-xx`, критерии
приёмки Дано / Когда / Тогда (с моделью), «Осталось уточнить» с плейсхолдером `[уточнить: Q-xx …]` в тексте
требования. В отчёте перед разделом 1 — блок «Кратко»: вердикт до → после и чем закрыт каждый блокер.

Прогон без модели (`LLM_PROVIDER=rules`, только правила и шаблонная подстановка) на этом файле ответов:

| Что | Значение |
|---|---|
| Ответов сопоставлено с вопросами прогона | 6 из 10: 3 конкретных, 2 уклончивых, 1 противоречивый (403 и 404 для чужой карты). Остальные 4 вопроса задаёт модель — в прогоне без неё их нет; ответы на них сопоставляются по служебной метке в прогоне с моделью |
| Изменено требований | 3 (R-013, R-014, R-039) |
| Новых требований | 1 (NEW-01 — адрес Prod, по ответу Q-06) |
| Закрыто блокеров | **3 из 6** (GET для изменения данных, 200 с ошибкой, пустой Prod) |
| Открытых замечаний | 33 → 31 |
| Осталось уточнить | 5 (2 уклончивых ответа, 1 противоречивый, 2 критичных вопроса без ответа) |

Цифры с моделью (формулировки «Стало» от модели, критерии приёмки) — после финального прогона.
